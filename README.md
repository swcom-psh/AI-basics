# 수행평가 주제 정하기 챗봇 (챗봇1)

학생이 대화하면서 자기 수행평가 주제를 데이터로 만들 수 있는 형태까지 다듬는 프로그램입니다.
**주제를 확정해 시트에 기록하는 것까지만** 합니다. CSV 생성은 하지 않습니다.

```
program/
  index.html            ← 학생 화면. GitHub Pages 에 올린다
  apps-script/코드.gs    ← 백엔드. 구글 시트에 붙여서 웹앱으로 배포한다
  README.md
```

---

## 1. 구글 클라우드 — OAuth 클라이언트

클라이언트 ID는 이미 코드에 들어 있습니다.
`508397953247-cec1cb0u7jmheuup6llmo05423lcibbu.apps.googleusercontent.com`

**승인된 JavaScript 원본**에 GitHub Pages 주소를 넣어야 로그인이 됩니다.

```
https://<깃허브아이디>.github.io
```

- 끝에 슬래시를 붙이지 않습니다.
- 저장소 이름이 붙는 주소(`https://아이디.github.io/repo/`)라도 **원본은 `https://아이디.github.io` 까지만** 적습니다.
- 로컬에서 시험해 보려면 `http://localhost:5500` 같은 주소도 함께 넣습니다.
- 리디렉션 URI는 쓰지 않습니다. 비워 두면 됩니다.

## 2. Apps Script — 백엔드

1. **키와 기록이 들어갈 스프레드시트를 엽니다.** (지금 쓰시는 「[인공지능기초] 수행평가 챗봇 기록 시트1」)
2. 확장 프로그램 → Apps Script → 기본 코드를 지우고 `apps-script/코드.gs` 를 통째로 붙여넣습니다.
3. `KEY` 시트 **A2 칸**에 OpenAI 키가 들어 있으면 그대로 씁니다.
   (프로젝트 설정 → 스크립트 속성에 `OPENAI_KEY` 를 넣어 두면 그쪽을 먼저 씁니다.)
4. `최초설정` 함수를 한 번 실행합니다. 권한 승인 창이 뜨면 허용합니다.
   실행 로그에 키를 제대로 찾았는지 나옵니다.
   예전(42열) 머리글이 있으면 **뒤에 새 열 19개가 자동으로 이어 붙습니다.** 기존 기록은 그대로 남습니다.
   (확정 버튼을 처음 누를 때도 같은 일이 일어납니다.)
5. 배포 → 새 배포 → 유형 **웹 앱**
   - **실행 사용자 : 나**
   - **액세스 권한 : 모든 사용자**
6. 나온 웹앱 주소를 복사합니다. (`https://script.google.com/macros/s/.../exec`)

> **이미 배포해 둔 것을 고칠 때** — 새 배포를 또 만들면 주소가 바뀝니다.
> [배포] → **배포 관리** → 연필(수정) → 버전 **새 버전** → 배포. 주소가 그대로 유지됩니다.
> 코드를 고친 뒤 이 과정을 거치지 않으면 예전 코드가 계속 돕니다.

> **액세스를 「모든 사용자」로 두는 이유**
> GitHub Pages(정적 페이지)에서 부르려면 이래야 합니다. 대신 **로그인 검사는 이 코드가 직접 합니다.**
> 요청마다 구글 ID 토큰을 받아 ① 우리 클라이언트 ID로 발급된 것인지 ② 확인된 계정인지
> ③ `@sdhs.gwe.hs.kr` 계정인지를 서버에서 검사하고, 하나라도 어긋나면 거부합니다.
> 주소를 알아도 학교 계정이 없으면 아무것도 못 합니다.

## 3. index.html — 주소 채우기

`index.html` 안 설정 부분에서 한 줄만 바꿉니다.

```js
const API_URL = 'PASTE_YOUR_APPS_SCRIPT_WEBAPP_URL_HERE';   ← 5번에서 복사한 주소
```

## 4. GitHub Pages

`index.html` 을 저장소에 올리고 Pages 를 켭니다. 그 주소를 클래스룸에 안내합니다.

배포 순서를 정리하면 — **웹앱 배포 → API_URL 채우기 → Pages 올리기 → OAuth 원본에 Pages 주소 등록** 입니다.

관리자 화면에서는 확정된 주제를 한 화면에 모아 보고, 학생별로 지울 수 있습니다.
관리자 판정은 서버에서 합니다. 화면 코드를 고쳐도 관리자가 되지 않습니다.

## 학생이 보는 흐름

구글 로그인 → 관심·학과 말하기 → 맞힐 것 고르기 → **화면에서 대상·정보·가설 정하기** → **마무리 서술 두 칸** → 오른쪽 패널이 다 채워지면 「주제 확정하기」 열림 → 확정

학생이 직접 하는 입력은 네 번(관심·학과 / 맞힐 것 / 대상·정보·가설 화면 / 마무리 서술)입니다.

학년·반·번호는 **메일 앞부분(학번)에서 서버가 직접 읽습니다.** 학생이 입력하지 않으므로 조작할 수 없습니다.

| 메일 앞부분 | 읽는 값 |
|---|---|
| `20262101` | 2학년 1반 1번 |
| `20262120` | 2학년 1반 20번 |

형식은 학년도 4자리 + 학년 1자리 + 반 1자리(1~9반) + 번호 2자리 = 정확히 8자리입니다.
이 형식이 아닌 계정(선생님 계정 등)만 학년·반·번호 입력 화면이 뜹니다 — 시험해 볼 때 씁니다.
확정할 때도 서버는 학번에서 읽은 값을 우선하고, 화면이 보낸 값은 학번 형식이 아닐 때만 씁니다.

- **이전으로 돌아가기** : 도우미의 지난 말마다 「↩ 여기서부터 다시」 버튼이 있습니다. 누르면 그 말 뒤의 대화를 지우고, 계획서와 단계도 그 시점으로 돌아가 그 말에 다시 답할 수 있습니다.
  시트의 채팅기록은 지우지 않고 「되돌리기」 줄을 남깁니다. 관리자 화면의 대화 보기에서 취소된 말은 흐리게 「취소됨」으로 보이고, 되돌린 위치도 표시됩니다.
  순서 번호는 배열 위치가 아니라 **순번 카운터**를 써서 되돌려도 번호가 겹쳐 기록이 누락되지 않습니다.
- 창을 닫아도 같은 기기·브라우저면 이어서 할 수 있습니다.
- **처음부터 다시 / 주제 다시 정하기**를 눌러도 구글 로그인은 풀리지 않습니다. 대화·계획서·입력만 처음으로 돌아가고 새 대화번호로 첫 인사부터 다시 시작합니다. 실수로 새로고침해도 이 탭에 남은 로그인 정보가 유효하면(약 1시간) 로그인 없이 이어서 들어갑니다. 로그아웃을 누르거나 탭을 닫으면 로그인 정보가 사라집니다.
- 다시 확정하면 이전 기록을 지우고 새로 씁니다.
- 로그인은 한 시간쯤 지나면 풀립니다. 그때는 다시 로그인하라는 안내가 나옵니다.

## 챗봇이 하는 일 — 4단계

`코드.gs` 위쪽 `시스템프롬프트` 에 있습니다. 이 부분만 고치면 챗봇 행동이 바뀝니다.

| 단계 | 학생이 하는 것 | 챗봇이 하는 것 |
|---|---|---|
| 1. 관심 분야·학과 | 관심 분야나 가고 싶은 학과를 말함 | 분야만 말하면 그 계열 학과 3~4개를 한 줄 설명과 함께 보여 주고 고르게 함 |
| 2. 맞힐 것(예측·분류) | y 후보 3~4개 중 고름. **예측/분류는 후보마다 [예측]·[분류]로 표시**돼 따로 묻지 않음 | 학생이 한 말에서 후보를 만들고 ①예측할 가치 ②시점 ③쓰임 ④흩어짐 ⑤민감성으로 걸러 냄. 같은 후보를 되풀이하지 않고 「더 줘」에는 새 후보를 냄 |
| 3. 대상·정보·가설 (화면 한 장) | **① 대상**을 후보 중 고르거나 직접 씀 **② 보기에서 정보 4~6개**를 체크(직접 추가 2개까지, 「보기 10개 더 보기」 가능) **③ 고른 정보마다 관계 가설**(늘어날 / 줄어들 / 관계없을 것 같다 + 선택 한 줄) | 주제에 맞춰 **실제로 수집할 수 있는 대상 후보 2~3개와 x 보기 10개**를 제시. 학생이 낸 값은 화면이 그대로 기록하고, 챗봇이 옮겨 적다 틀려도 화면이 바로잡음 |
| 4. 마무리 서술 | 두 칸을 직접 씀 **① 내 주제를 한두 문장으로** **② 이 예측·분류를 어떤 문제 해결에 활용할 수 있는지**(누가, 어떤 문제를, 어떻게) | 학생이 쓴 글을 그대로 기록하고, 빠진 것이 있으면 그 칸만 다시 쓰게 함. 대신 써 주지 않음 |

**x 보기** 는 숫자나 예/아니오로 구할 수 있고 예측 시점에 알 수 있는 값만 냅니다. 과거 기록·달력·날씨·대상의 특성·운영 조건 중 세 종류 이상을 섞고, y와 이어질 가능성이 큰 것과 약한 것을 함께 넣습니다(어느 쪽인지는 알려 주지 않습니다). 설문이나 주관 점수가 필요한 값은 내지 않습니다.
보기와 고른 것은 시트에 남아(`제시한보기`, 정보 열의 `떠올린사람` = 보기 / 학생) 수행평가 뒤에 어떤 정보를 골랐는지 분석할 수 있습니다.
학생이 화면에서 낸 값(대상, 고른 정보, 가설, 마무리 서술)은 브라우저가 따로 보관하고, 챗봇이 옮겨 적다 틀리면 학생이 낸 값으로 바로잡습니다. 「이전으로 돌아가기」를 하면 그 뒤에 낸 값도 함께 지워집니다.

- 후보는 같은 것을 되풀이하지 않습니다. 「또 다른 예시」를 누르면 앞에 나온 것과 소재가 겹치지 않는 새 후보를 보여 주고, 「10개 더 알려줘」처럼 개수를 말하면 그만큼(최대 10개) 한 번에 보여 줍니다.
  영화·지하철·따릉이·전력 같은 실제 자료 소재는 후보 중 1~2개까지만 쓰고, 자료가 없는 주제도 학생의 관심과 이어지면 제안합니다(자료는 선생님이 나중에 만듭니다).
- 숫자(값의 범위·통계)는 대화에서 다루지 않습니다. 선생님이 CSV를 만들 때 실제 자료로 정합니다.
- 주제를 고른 이유와 기대 효과는 수행평가지(1-1·1-3)에서 학생이 직접 씁니다.
- x가 y를 늘리는지 줄이는지는 챗봇이 말하지 않습니다. 수행평가 때 모델로 확인합니다.
- 기계학습 방법·알고리즘·파이썬 코드는 알려주지 않습니다.
- 확정 버튼을 눌러도 서버가 규칙으로 한 번 더 검사합니다.

### 학생의 판단을 지키는 장치
세특의 근거가 되도록, 챗봇이 학생 말에 맞장구치기만 해서는 확정되지 않게 했습니다.

| 장치 | 내용 |
|---|---|
| 이유 없이 빼자고 하면 되묻기 | 「별로」「말고」만으로는 바로 바꾸지 않고 이유를 한 번 묻습니다. 뺀 정보와 이유는 시트 `제외한정보`에 남습니다. |
| 정보마다 가설 | 고른 정보 하나하나에 「y가 늘어날 / 줄어들 / 관계없을 것 같다」 가설을 학생이 고르고 원하면 한 줄을 덧붙입니다. 챗봇은 가설을 대신 쓰거나 맞고 틀림을 판정하지 않습니다. |
| 마무리 서술 두 가지 | 「내 주제」와 「문제 해결 활용」을 각각 15자 이상 학생이 직접 씁니다. 「ㅇㅇ」「굳」 같은 한두 글자는 인정하지 않고, **서버가 두 문장이 학생 메시지에서 나온 것인지** 확인합니다(챗봇이 대신 쓴 문장은 거부). |
| 대상은 구체적 이름 | 「서울의 한 지하철역」「한 학급」처럼 뭉뚱그린 말은 거부합니다. 학생이 고르거나 직접 쓴 이름이어야 합니다. |
| 시점과 예보 | 예측 시점이 「일주일 전」「한 달 전」인데 「(예보)」 정보가 있으면 거부합니다. |

세 번 답을 못 해 선생님께 넘어간 학생(`도움요청`)은 가설·확인 문장·학생 제안 수가 면제됩니다.
이 규칙은 `코드.gs` 의 `검사_()` 와 `index.html` 의 `검사()` 에 같은 내용으로 들어 있습니다. 한쪽만 고치면 어긋납니다.

### 주제를 걸러내는 이유

「환자 체온 예측」처럼 재면 바로 아는 값, 정상 범위가 좁아 맞힐 거리가 없는 값은 세특에 적기 어렵습니다.
챗봇이 그 분야 현장 사람의 눈으로 왜 걸리는지 말하고, 학생의 관심은 살린 채 문제 설정만 바꾼 후보를 보여 줍니다.

### 계획서 화면

오른쪽에 「수행평가 계획서」 한 장이 대화할수록 채워집니다. Ⅰ 주제 / Ⅱ 맞힐 것(y) / Ⅲ 맞히는 데 쓸 정보(x).
정보마다 **내가 떠올림 / 보기에서 고름** 이 표시되고, 오른쪽 칸에 학생의 가설이 보입니다.

## 시트1 구조

학생 한 명당 한 행. 맨 끝 두 열에 대화 기록이 함께 들어갑니다.

```
시각 · 메일 · 학번 · 이름 · 학년 · 반 · 번호
트랙 · 주제 · 대상 · 예측시점 · 자료등급 · 연계학과
타깃_이름 · 타깃_단위 · 타깃_실자료
범주A · 범주B · 분류기준
정보1_이름 · 형태 · 떠올린사람 · 실자료      (정보4까지)
주제점검 · 점검메모
대신요청수 · 도움요청수 · 학생제안수(직접 적은 정보 수)
주고받은수 · 대화내용(JSON)                    ← 여기까지 42열 (예전과 같음)
정보5_이름 · 형태 · 떠올린사람 · 실자료  /  정보6_… (같은 4열)
정보1_가설 … 정보6_가설
대상확인 · 제외한정보 · 확인문장 · 제시한보기 · 활용방안      ← 뒤에 덧붙인 19열
```

모두 61열입니다. 예전 기록의 열 위치를 건드리지 않으려고 새 열은 맨 끝에 붙였습니다.
`형태`는 숫자 / 예아니오, `떠올린사람`은 학생(직접 적음) / 보기(체크 목록에서 고름) / 챗봇(예전 기록), `제시한보기`는 학생에게 보여 준 보기 전부, `활용방안`은 학생이 쓴 「이 예측·분류를 어떤 문제 해결에 쓸 수 있는지」입니다.
`실자료`와 `자료등급`(A/B/C)은 챗봇의 추정이라, CSV를 만들 때 실제로 받아지는지 확인해야 합니다.

## 공용 컴퓨터와 동시 접속

- 구글 로그인은 자동 계정 선택을 껐습니다. 앞 학생이 크롬에서 로그아웃하지 않아도 다음 학생이 그 계정으로 자동 입장하지 않고, 버튼을 눌러 계정을 고릅니다.
- 상단과 완료 화면에 「로그아웃」 버튼이 있습니다. 대화는 브라우저에 남아 있어서 같은 계정으로 다시 로그인하면 이어서 할 수 있습니다.
- 한 반이 동시에 보내 OpenAI 분당 한도(429)나 일시 오류가 나면, 서버가 두 번, 화면이 두 번 더 조금씩 늦춰 다시 시도합니다. 학생 화면에는 "사람이 많아 잠깐 기다리는 중"이 뜹니다.
- 그래도 자주 막히면 platform.openai.com → Limits 에서 계정 등급(Tier)의 분당 토큰 한도를 확인하세요. 호출 한 번이 1만 토큰 가까이 됩니다.

## 관리자 화면

- **대화** 버튼 : 그 학생의 채팅기록을 오른쪽 창으로 봅니다. 「처음부터 다시」로 나뉜 대화는 1번째, 2번째로 묶여 보이고, 확정한 시점도 표시됩니다.
- **겹침** 표시 : 맞힐 것과 주제가 비슷한 학생이 있으면 주제 옆에 「겹침 n」이 붙습니다. 마우스를 올리면 누구와 겹치는지 보입니다.
  같은 주제라도 데이터를 만들 때 대상(역·지점)·기간을 학생마다 다르게 주면 됩니다.

## 채팅기록 시트

말 한 마디당 한 줄씩, 대화할 때마다 바로 쌓입니다. 확정하지 않고 나간 학생의 대화도 남습니다.

```
시각 · 학번 · 이름 · 학년 · 반 · 번호 · 대화번호 · 순서 · 보낸이 · 내용 · 단계 · 메일
```

- `보낸이` : 학생 / 도우미 / 화면(첫인사·빈칸 점검처럼 화면이 자동으로 보낸 말) / 확정(계획서를 낸 시점, 내용 칸에 주제)
- `대화번호` : 「처음부터 다시」를 누르면 새 번호가 됩니다. 한 학생이 몇 번 다시 했는지 여기서 보입니다.
- 한 학생 대화만 보려면 필터로 학번을 고르고 대화번호·순서로 정렬하면 됩니다.
- 시트를 미리 만들지 않아도 `최초설정()` 이나 첫 대화 때 자동으로 만들어지고 머리글도 들어갑니다.
- 이름은 계정의 이름 칸(3자)에서 읽습니다. 성 칸의 학번은 떼어 냅니다.

CSV를 만들 때 필요한 것이 전부 이 한 시트에 있습니다.
