# 수행평가 주제 정하기 챗봇 (챗봇1)

학생이 대화하면서 자기 수행평가 주제를 데이터로 만들 수 있는 형태까지 다듬는 프로그램입니다.
**주제를 확정해 시트에 기록하는 것까지만** 합니다. CSV 생성은 하지 않습니다.

```
program/
  index.html            ← 학생 화면. GitHub Pages 에 올린다
  apps-script/코드.gs    ← 백엔드. 구글 시트에 붙여서 웹앱으로 배포한다
  README.md
```

---

## 1. 구글 클라우드 — OAuth 클라이언트

클라이언트 ID는 이미 코드에 들어 있습니다.
`508397953247-cec1cb0u7jmheuup6llmo05423lcibbu.apps.googleusercontent.com`

**승인된 JavaScript 원본**에 GitHub Pages 주소를 넣어야 로그인이 됩니다.

```
https://<깃허브아이디>.github.io
```

- 끝에 슬래시를 붙이지 않습니다.
- 저장소 이름이 붙는 주소(`https://아이디.github.io/repo/`)라도 **원본은 `https://아이디.github.io` 까지만** 적습니다.
- 로컬에서 시험해 보려면 `http://localhost:5500` 같은 주소도 함께 넣습니다.
- 리디렉션 URI는 쓰지 않습니다. 비워 두면 됩니다.

## 2. Apps Script — 백엔드

1. **키와 기록이 들어갈 스프레드시트를 엽니다.** (지금 쓰시는 「[인공지능기초] 수행평가 챗봇 기록 시트1」)
2. 확장 프로그램 → Apps Script → 기본 코드를 지우고 `apps-script/코드.gs` 를 통째로 붙여넣습니다.
3. `KEY` 시트 **A2 칸**에 OpenAI 키가 들어 있으면 그대로 씁니다.
   (프로젝트 설정 → 스크립트 속성에 `OPENAI_KEY` 를 넣어 두면 그쪽을 먼저 씁니다.)
4. `최초설정` 함수를 한 번 실행합니다. 권한 승인 창이 뜨면 허용합니다.
   실행 로그에 키를 제대로 찾았는지 나옵니다.
   **예전 버전으로 이미 머리글을 만들어 두었다면 시트1의 1행을 지우고 다시 실행하세요.**
   열이 68개로 늘었습니다. (로그에 예전 형식이라고 경고가 뜹니다.)
5. 배포 → 새 배포 → 유형 **웹 앱**
   - **실행 사용자 : 나**
   - **액세스 권한 : 모든 사용자**
6. 나온 웹앱 주소를 복사합니다. (`https://script.google.com/macros/s/.../exec`)

> **이미 배포해 둔 것을 고칠 때** — 새 배포를 또 만들면 주소가 바뀝니다.
> [배포] → **배포 관리** → 연필(수정) → 버전 **새 버전** → 배포. 주소가 그대로 유지됩니다.
> 코드를 고친 뒤 이 과정을 거치지 않으면 예전 코드가 계속 돕니다.

> **액세스를 「모든 사용자」로 두는 이유**
> GitHub Pages(정적 페이지)에서 부르려면 이래야 합니다. 대신 **로그인 검사는 이 코드가 직접 합니다.**
> 요청마다 구글 ID 토큰을 받아 ① 우리 클라이언트 ID로 발급된 것인지 ② 확인된 계정인지
> ③ `@sdhs.gwe.hs.kr` 계정인지를 서버에서 검사하고, 하나라도 어긋나면 거부합니다.
> 주소를 알아도 학교 계정이 없으면 아무것도 못 합니다.

## 3. index.html — 주소 채우기

`index.html` 안 설정 부분에서 한 줄만 바꿉니다.

```js
const API_URL = 'PASTE_YOUR_APPS_SCRIPT_WEBAPP_URL_HERE';   ← 5번에서 복사한 주소
```

## 4. GitHub Pages

`index.html` 을 저장소에 올리고 Pages 를 켭니다. 그 주소를 클래스룸에 안내합니다.

배포 순서를 정리하면 — **웹앱 배포 → API_URL 채우기 → Pages 올리기 → OAuth 원본에 Pages 주소 등록** 입니다.

## 챗봇이 지키는 조건

`코드.gs` 위쪽 `시스템프롬프트` 에 있습니다. 이 부분만 고치면 챗봇 행동이 바뀝니다.

| 조건 | 내용 |
|---|---|
| 유형 | 예측 또는 분류. 분류는 두 범주만 |
| 맞히려는 값 | 하나. 이름·단위·대략 범위까지 |
| 쓸 정보 | **챗봇이 3~4개를 확정해서 제시**하고, 학생은 빼거나 바꾸거나 더함 |
| 주제 걸러내기 | ①예측할 가치 ②시점 ③쓰임 ④흩어짐 ⑤민감성 — 다섯 가지를 다 통과해야 함 |
| 값 범위 | **화면이 웹에서 실제 자료를 찾아** 출처·링크와 함께 초안을 보여 주고 학생이 확인 |
| 영향 방향 | 학생은 **예상(가설)만** 적고, 데이터에 쓰는 실제 방향은 챗봇이 자료 근거로 정함 |
| 무관 변수 | 챗봇이 **말없이** 하나 넣음. 학생에게 묻지도 알리지도 않음 (핵심속성 추출 수업용) |
| 이유·기대 | 학생 말로 두세 문장. 수행평가지 1-1·1-3에 그대로 씀 |

기계학습 방법·알고리즘·파이썬 코드는 알려주지 않습니다.

### 주제를 걸러내는 이유

「환자 체온 예측」처럼 재면 바로 아는 값, 정상 범위가 좁아 맞힐 거리가 없는 값은
세특에 적기 어렵습니다. 챗봇이 그 분야 현장 사람의 눈으로 왜 걸리는지 한두 문장으로 말하고,
**학생의 관심은 살린 채 문제 설정만 바꾼 후보**를 보여 줍니다.
(체온 예측 → 입원 첫날 정보로 퇴원까지 걸리는 날 수 예측)
분야별 고쳐 잡는 예가 `시스템프롬프트` 안에 들어 있습니다. 필요하면 분야를 더 넣으면 됩니다.

### 예상은 가설로만 받습니다

학생이 "기온↑ → 판매량↑"이라고 써 놓고 그 값으로 데이터를 만들면, 모델을 돌려서
자기가 쓴 걸 그대로 다시 보게 됩니다. 발견이 아니라 답 맞추기입니다.

그래서 **학생의 답은 「예상」 칸에만 들어가고 데이터에는 쓰지 않습니다.**
데이터의 실제 방향은 챗봇이 찾은 자료와 분야 원리로 정하고, 세기를 일부러 흩어 놓습니다
(3~4개 중 적어도 하나는 강하게, 하나는 약하게).

- 학생 화면에는 **예상만** 보입니다. 실제 방향은 답변·요약 어디에도 나오지 않습니다.
- 시트에는 `정보n_학생예상` 과 `정보n_실제영향` 이 나란히 남습니다. 관리자 화면에서 다르면 `≠` 표시가 붙습니다.
- 실습 뒤 「예상 vs 모델 결과」를 비교하는 것이 결론이 됩니다.
  **수행평가지(ipynb)에 그 비교 칸을 아직 넣지 않았습니다. 따로 작업해야 합니다.**
- 대화 기록(JSON)은 브라우저 저장소에 그대로 남으므로, 개발자 도구를 열 줄 아는 학생은
  실제 방향을 볼 수 있습니다. 막으려면 서버에서 실제 방향을 떼고 보내야 하는데,
  그만한 일은 아니라고 봅니다.

### 데이터는 3등급으로 만듭니다

학생 주제 대부분은 행 단위 공개 자료가 없습니다. KOSIS·검색으로 나오는 건 「전국 연간 평균」 같은
집계표라서 모델에 바로 못 넣습니다. 그래서 등급을 나눕니다.

| 등급 | 방식 | 해당 주제 |
|---|---|---|
| **A** | 실제 데이터 그대로 | 따릉이·지하철·전력·미세먼지·교통사고·영화처럼 공공 API가 행 단위로 주는 것 |
| **B** | **실제 축 + 합성 타깃** | 날짜 축을 깔고 기온·강수·요일·공휴일은 실제 관측값, 타깃만 생성 |
| **C** | 전부 합성 (분포는 검색한 통계에 맞춤) | 개별 점포·병동처럼 공개 자료가 전혀 없는 주제 |

B가 가장 많을 것입니다. 관계는 합성이어도 **입력의 분포·계절성·결측·이상치는 진짜**라서,
학생이 만나는 전처리 문제가 실제 문제가 됩니다.

실제 자료로 채울 수 있는 값은 프롬프트의 「실제 자료로 채울 수 있는 값」 목록에 있습니다 —
기상청 ASOS, 달력·공휴일, 에어코리아, 공공데이터포털(지하철·따릉이), 한국전력, 도로교통공단,
소방청, KOBIS, KOSIS, 한국은행·오피넷. 챗봇은 **쓸 정보 3~4개 중 최소 하나를 이 목록에서** 고릅니다.

시트의 `자료등급`과 `정보n_실자료` 는 **챗봇의 판단이지 확정이 아닙니다.** 데이터를 만들 때
실제로 받아지는지 확인해야 합니다. 관리자 화면에서 A/B/C 인원수와 항목별 출처가 한눈에 보입니다.

CSV는 **결측치 정도만** 넣어 줍니다(중복행·단위 섞임·깨진 컬럼명은 넣지 않음).

### 자료는 화면이 찾아 줍니다

범위를 정할 차례가 되면 챗봇이 항목마다 검색어를 내놓고, 서버가 **OpenAI 웹 검색**으로
실제 자료를 찾아 요약과 링크를 파란 카드로 보여 줍니다. 학생은 링크를 열어 맞는지 보고
「네」 또는 바꿀 숫자만 말하면 됩니다. 카드 아래에는 네이버·구글·구글학술·KOSIS
직접 검색 링크도 함께 붙습니다.

- 자료에 없는 값(예/아니오, 날짜 같은 정의로 정해지는 값)은 검색하지 않고 바로 기록합니다.
- 자료를 못 찾으면 챗봇이 숫자를 지어내지 않고 학생에게 대략 얼마쯤일지 묻습니다.
- 근거는 「자료: 제목 (링크)」 / 「학생 추정 — 자료 없음」 / 「정의상 정해짐」 셋 중 하나로 남습니다.

확정 버튼을 눌러도 서버가 규칙으로 한 번 더 검사합니다. 특성이 3개 미만이거나 범위가 뒤집혔거나
단위가 없거나 영향 방향이 비었으면 저장하지 않고 무엇이 부족한지 알려 줍니다.

## 시트1 구조

학생 한 명당 한 행. 맨 끝 두 열에 대화 기록이 함께 들어갑니다.

```
시각 · 메일 · 학번 · 이름 · 학년 · 반 · 번호
트랙 · 주제 · 대상 · 예측시점 · 자료등급
타깃_이름 · 단위 · 최소 · 최대 · 근거 · 실자료
범주A · 범주B
정보1_이름 · 단위 · 최소 · 최대 · 근거 · 학생예상 · 실제영향 · 실제큰쪽 · 실자료   (정보4까지)
무관_이름 · 단위 · 최소 · 최대
고른이유 · 기대효과
주제점검 · 점검메모
대신요청수 · 도움요청수
주고받은수 · 대화내용(JSON)
```

모두 68열입니다.
`주제점검`은 다섯 조건을 통과했는지(O / △), `점검메모`는 «현장에서 누가 언제 무엇을 결정하려고 쓰는지» 한 문장입니다.
`학생예상`은 가설, `실제영향`은 데이터 생성에 실제로 쓰는 값입니다. **CSV를 만들 때 쓰는 건 `실제영향` 쪽입니다.**
`대신요청수`는 학생이 "알아서 해 주세요" 류로 답한 횟수, `도움요청수`는 챗봇이 선생님을 불러 달라고 멈춘 횟수입니다.
세특을 쓸 때 참고하시라고 남겨 둔 값이고, 점수와는 무관합니다.

CSV를 만들 때 필요한 것이 전부 이 한 시트에 있습니다.

## 비용

`코드.gs` 맨 위에서 바꿉니다.

- `MODEL` (대화) 기본값 **`gpt-4.1`** — 주제를 걸러내는 판단이 필요해서 큰 모델을 씁니다.
- `SEARCH_MODEL` (자료 찾기) 기본값 **`gpt-4.1-mini`** + 웹 검색 도구.

84명이 각자 10~15턴 대화하고 학생당 3~4번 웹 검색을 한다고 보면 전체 **2~3만 원** 정도입니다.
비용을 줄이려면 `MODEL` 을 `gpt-4.1-mini` 로 내리면 되는데, 주제를 걸러내는 판단이 함께 무뎌집니다.
먼저 선생님 계정으로 몇 번 돌려 보고 platform.openai.com 의 사용량을 확인한 뒤 정하시면 됩니다.

## 키 관리

- 키는 `KEY` 시트 A2에 있습니다. **이 스프레드시트에는 학생 대화 기록도 함께 쌓입니다.**
  누군가에게 시트를 공유할 일이 생기면 키까지 넘어갑니다. 공유하지 마세요.
- 더 안전하게 두려면 스크립트 속성에 `OPENAI_KEY` 로 옮기고 A2를 비우면 됩니다. 코드는 그대로 동작합니다.
- 키가 노출된 것 같으면 platform.openai.com에서 폐기하고 새로 발급한 뒤 A2만 바꾸면 됩니다.

## 수업 전 점검
